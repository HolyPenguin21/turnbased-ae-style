# Пакет 4: движение и observation

База: `5f752169`, ветка `refactor/non-ai-package-4`. Изменение архитектуры владения состоянием; политики выбора ИИ не меняются.

## Движение

`ArmyMovementOperation` копирует маршрут и хранит Pending/Moving/Resolving/Finishing/Settled. `ArmyData.Movement` и `IsMovementBusy` доступны без marker/input. `CurrentHex` операции и индекс `ArmyRegistry` совпадают после каждого оплаченного законного шага; MP каждого актуального участника списаны одновременно с этим шагом. `ArmyController.CurrentHex` — совместимый read adapter. `ForMap` использует существующий terrain/CanEnter и AviationRules, а планировщик приказа сохраняет HexPathfinder.

Activation выполняется через ArmyActions только перед первым законным и доступным шагом, в одной notification mutation с входом. До этого отмена/отказ ничего не списывают. Для следующего шага повторно проверяются owner, registration, container eligibility, adjacency, terrain, surviving roster и effective MP/transport. `LastStepWasVisible` фиксирует видимость до входа: после re-key registry уже пересчитана видимость.

`ForOrder` добавляет entry/arrival effects: AA/strike через существующую AviationCombatOperation/презентер либо headless adapter; stealth после реакции; остановку на clean event/контакте/новом чужом здании; takeover через BuildingRegistry и бой через существующий `TryBeginBattleAt` → BattleEncounterCoordinator. Selection обновляет панели/маркеры по `ArmyMovementArrival`, а не определяет endpoint или оплачивает шаг. Resident reveal остаётся на прежнем encounter entrypoint; его отложенная очередь живёт до OnDestroy и обслуживается даже при disabled input. Отключение всей scene останавливает очередь.

`Result` — immutable Kind/Hex/EnteredSteps. `Completed` публикуется один раз после effects и закрытия busy state. Arrived и законный partial Interrupted выполняют arrival effects один раз. Rejected, Cancelled и Dead их не выполняют. Только один Run может вести operation; explicit TryEnterNextStep/Settle остаются адаптером raw ForMap и не обходят pending effects. Explicit cancel закрывает подвешенный reaction; presenter cancellation отличается от обычного stop. Cancellation не откатывает уже вошедший hex/MP. Death/removal/registry reset закрывают pending operation. Анимационные итераторы проверяют владение/epoch и не применяют старый финальный transform после отмены.

Cancel не вызывает успешный `onSettled`; отдельный cancellation callback используется для reconciliation. Старые coroutine handles и termination handlers не могут остановить заменяющий приказ из `Completed`. Синхронный event Skip передаёт прежний intent через presentation settlement inline, до наблюдения idle состояния AI waiter; cancel/replacement удаляют continuation.

`ArmyRegistry.HasMovementInProgress` объединяет `ArmyData.IsMovementBusy`, controller presentation busy и pending settlement continuation; существующий `CanSaveMatch` уже использует этот контракт. Пакет 5 продолжает использовать его вместе с другими application busy gates. Settled означает отсутствие незавершённых movement effects. Пакет 8 подписывается на `Completed`/результат и показывает анимацию; `ArmyController.MoveAlong` и `SettleThen` остаются compatibility adapters.

## Наблюдение

`MapObservationSystem` вызывается после committed visibility/content mutations и слушает stealth, building transition и relocation. Он использует каждого legitimate viewer, не зависит от selection enabled или CurrentViewer и не использует debug reveal для знаний. Building transition сохраняет prior witnesses до потери собственного источника видимости. При crossing края обзора сохраняется endpoint действительно наблюдаемого шага. Payload захватывается до выхода из видимости, публикуется после commit, а frozen marker переносится из собственного viewer cache. Скрытые building defense, изменённые roster и renderer appearance назначения не читаются. Наблюдённый endpoint добавляется только в everSeen, не в current visibility/visited; это сохраняет допустимость позиции для save codec. Последующие скрытые изменения record не обновляют.

VisionSystem отдельно хранит current visibility, visited ground и everSeen; воздушный пролёт увеличивает visibility/everSeen, но не visited. Personal stealth/detection остаются в StealthSystem. AiMapMemory остаётся отдельным владельцем decision memory. Нейтральные map armies тоже получают immutable snapshots: их прежняя долгая память сохраняется до повторного наблюдения, без live everSeen bypass в marker/layout. Transient event guards исключаются существующим `HexEventRegistry.IsEventGuardArmy`. Старый save без frozen neutral payload не достраивает его из hidden live world.

HumanVisualMemory хранит `ObservedArmy`/`ObservedUnit`: readonly поля и собственные roster/abilities/costs, authored art/card/player identity references. Captured owner, movement, defense, attachments, roster не читаются заново из hidden world. `ArmySighting.Army` создаёт новый detached compatibility display (Id=-1, projected unit IDs), а не возвращает mutable backing storage. Чтение/capture/restore не создают live IDs, transport membership или activation coverage; visual activation flag записывается отдельно. Historical restore не резервирует live IDs: за high-water marks отвечает MatchIdentityState.

`GameTurnController` истекает player-army memory на прежней границе TurnChanging; память нейтралов остаётся до корректирующего наблюдения. После replenishment/activation reset явно публикуются content changes и повторно наблюдается весь текущий обзор игрока — неподвижный противник не пропадает из памяти из-за expiry при неизменной видимости. Frozen appearance projection продолжает слушать committed observations до OnDestroy, даже при отключённом input. Renderer clones и viewer caches сохраняются раздельно; display restore проверяет соответствие immutable observation и frozen marker. Frozen visual codec/schema остаются совместимыми. Локальный refresh вместо существующей полной reconciliation не вводится.
