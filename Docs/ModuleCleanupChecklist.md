# Чек-лист чистки модуля

Шаблон для поочерёдной чистки модулей AI (первый — `Assets/Scripts/Ai/V2/Housekeeping/`).
Дополняется по ходу работы: каждый пункт, которого не хватило, добавляется сюда.
Общие правила — `AGENTS.md`; таксономия слоёв — `Assets/Scripts/Ai/V2/ARCHITECTURE.md`.

## Принципы

- Модуль чистится без изменения поведения; найденные ошибки исправляются полностью, ничего не откладывается
  (исключение — только явное решение владельца записать пункт в технический долг).
- Новые классы не создаются, пока существующий класс остаётся удобного размера: логика группируется в нём.
- Перед переносом логики в другой класс/модуль он анализируется так же, как сам модуль.
- Коммиты-переносы (поведение не меняется) отделены от коммитов-исправлений (поведение меняется и объяснено).
- Если исправление требует выбора игрового поведения — вопрос владельцу; однозначные исправления — сразу.

## 1. Анализ модуля

- [ ] Карта: классы, публичные методы, кто вызывает модуль и кого вызывает он (включая тесты, `Tools/`,
      reflection, строковые имена в `Setup/MatchStateInventory.cs`, сохранения).
- [ ] Чужая логика внутри модуля (по таксономии слоёв).
- [ ] Дубли: внутри модуля; пары «виртуальная модель / живой объект» для одного правила; копии правил
      соседних слоёв. Для каждого дубля — какая копия остаётся единственной.
- [ ] Мусор: методы/поля без вызывающих, записываемые, но не читаемые поля, настройки без читателей,
      лишние `using`, тестовые обёртки в игровом коде, устаревшие сообщения журнала.
- [ ] Защитный шум (проверки на null там, где инвариант гарантирован) — проверки только на входах.
- [ ] Детерминизм: каждая сортировка, от которой зависит выбор, заканчивается устойчивой развязкой.
- [ ] Видимость: `public` только для реальных внешних потребителей.
- [ ] Горячие места (по замеру): аллокации и повторные пересчёты в циклах кандидатов.

## 2. Анализ целевого места (для каждого переноса)

- [ ] Те же проверки, что в п.1, для класса-получателя.
- [ ] Размер после переноса остаётся удобным; нет ли там уже такой же логики.
- [ ] Согласованность: то же понятие не реализовано у соседей иначе.

## 3. Найденные ошибки (каждая)

- [ ] Проверка исходного сбоя (кейс стенда предпочтительнее отдельного юнит-теста).
- [ ] Проверить тот же шаблон ошибки в соседних механиках.

## 4. Тесты модуля

- [ ] Список тестов с решением «оставить / удалить» и причиной; показать владельцу до удаления.
