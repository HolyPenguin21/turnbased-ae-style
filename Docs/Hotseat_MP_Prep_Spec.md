# ТЗ: хотсит + подготовка к мультиплееру (Steam)

Дата: 2026-11-11. Базовая ревизия: master `6a55e9f3`. Unity 6000.5.4f1.
Исполнитель: агент в новом чате. Перед началом прочитать `AGENTS.md`, `Tools/ai-verify/README.md`,
этот документ целиком, затем перепроверить по коду каждую ссылку ниже (код — источник истины,

## 0. Цель и границы

**Цель.** Локальный хотсит: 2+ людей за одним компьютером (+ любые AI), каждый со своим туманом
войны, рукой, ресурсами и решениями. Реализация сразу строится на абстракциях, которые потом
переиспользует сетевой мультиплеер (хост-авторитетная модель).

**В объёме:**
- этап A — модель управления игроком, «чей экран», правило наград;
- этап B — маршрутизация решений с шторкой передачи, бой человек-против-человека, сохранение/загрузка хотсит-матча.

**Вне объёма (не делать):**
- сеть, Steamworks, лобби, транспорт;
- сериализуемые команды для всех действий игрока (отдельный этап после хотсита);
- детерминизм RNG;
- несколько аккаунтов/профилей, выбор аккаунта;
- хотсит в кампании (кампания остаётся строго с одним человеком);
- изменения баланса и AI-логики;
- автоматические UI-тесты (правило владельца: UI не покрывается тестами).

## 1. Решения владельца (зафиксированы)

| # | Решение |
|---|---|
| D1 | Мета-прогрессия — один локальный аккаунт. Все награды хотсит-матча падают в него. |
| D2 | Правило награды аккаунта: **победа**, если выжившим стал любой человек; **поражение**, только когда выбыл последний живой человек; **одна награда на матч**. Фракция карт: победа — фракция победившего человека; поражение — фракция последнего выбывшего человека. Ничья — как сейчас (без наград вне кампании). |
| D3 | Бой человек-против-человека в хотсите полностью открыт: обе стороны управляются за одним экраном, шторка внутри боя не нужна. Рука тактик показывается для стороны, которая сейчас действует. |
| D4 | Сохранение посреди хотсит-матча делается сразу (переиспользуется для продолжения/переподключения в MP). |
| D5 | Хотсит — первый шаг к MP: вводимые абстракции обязаны работать и для `RemoteHuman` без переделки. |

## 3. Целевая архитектура (новые понятия)

Имена — рекомендованные. Перед созданием проверить, нет ли аналогов (AGENTS.md: переиспользовать
существующее). Пространства имён — по месту (`Game.Players`, `Game.Core`, `Game.UI`).

### 3.1 `PlayerControl` — кто управляет игроком
```csharp
public enum PlayerControl { Ai, LocalHuman, RemoteHuman }
```
- `PlayerSetupData.Control` — источник истины.
- `IsHuman` остаётся и означает «управляется человеком» (`Control != Ai`). Сейчас это **поле**
  (`Players/PlayerSetupData.cs:21`); сделать свойством с сеттером
  (`set => Control = value ? LocalHuman : Ai`), чтобы ~200 мест в тестах с `IsHuman = true`
  продолжили компилироваться. Проверить, что `PlayerSetupData` нигде не сериализуется Unity-сериализатором/
  `JsonUtility` по полю `IsHuman` (поиск по `IsHuman` в Saves, Setup, Campaign; кодеки пишут `human` вручную).
- `RemoteHuman` в этом ТЗ нигде не создаётся, но каждая развилка обязана корректно обрабатывать
  его как «человек, не за этим экраном» (это и есть подготовка к MP).
- В сохранении: **не менять** форму данных (`MatchPlayerData.human` остаётся bool → `LocalHuman`).
  Хеш схемы (`MatchSaveSchema.Hash`) не должен измениться; если изменится — остановиться и спросить владельца (Р7).

### 3.2 `LocalSeat` — чей сейчас экран
Одно место, отвечающее на вопрос «приватный интерфейс какого игрока показан на этом экране».
```csharp
public static class LocalSeat
{
    public static PlayerSetupData Current { get; }   // null = ни один (шторка / AI-наблюдатель)
    public static event Action Changed;
    internal static void Set(PlayerSetupData player); // только GameTurnController / restore / setup
}
```
- Одиночная игра: всегда единственный человек (поведение не меняется).
- Хотсит: устанавливается на человека **после** подтверждения шторки его хода; на время шторки — `null`.
  Во время хода AI остаётся последний человек (см. 5.3).
- AI-наблюдатель: `null` (наблюдательские режимы продолжают работать как сейчас).
- MP (будущее): фиксирован на локальном игроке.
- Весь UI, который сейчас использует `GameSession.FindHumanPlayer()/FindHumanRoot()` как «мой игрок»,
  переходит на `LocalSeat.Current` и **пересвязывается по `Changed`** (не кешировать навсегда).
- `GameSession.FindHumanPlayer()` удалить или переименовать по смыслу, чтобы не осталось
  неоднозначного «первого человека»: где нужен «любой человек в матче» — `GameSession.HasHuman`/
  `HumanPlayers`; где «мой» — `LocalSeat.Current`. Каждое место классифицировать (раздел 8.1).

Связь с туманом: `VisionSystem.CurrentViewer` — это «чью картину мира рисуем». Он остаётся отдельным
(в наблюдателе зритель ≠ сиденье), но в хотсите синхронизируется с `LocalSeat` при подтверждении хода.
**Никогда не присваивать `CurrentViewer = null` в матче с людьми**: null = «видно всё» (fail-open,
`VisionSystem.cs:115`).

### 3.3 `PlayerDecisionRouter` — решения вне своего хода
Единая точка: «игроку X нужно принять решение D». Маршрутизация по `Control` и по `LocalSeat`:

| Владелец решения | Действие |
|---|---|
| AI | политика AI (как сейчас: `SuggestedFire`, `ChooseAiTactic` и т.п.) |
| LocalHuman == `LocalSeat.Current` | показать popup сразу (как сейчас) |
| LocalHuman ≠ `LocalSeat.Current` | шторка передачи «Решение игрока B» → `LocalSeat`=B, зритель=B → popup → шторка «Вернуть игроку A» → `LocalSeat`/зритель = A |
| RemoteHuman | `NotSupportedException` в этом ТЗ (точка расширения для сети) |

- Решение — объект (по образцу `AaDecisionRequest`/`MatchDecision`): завершается один раз,
  отменяется со сменой поколения матча.
- Корутинные потребители (`AviationCombatPresenter`, бой) ждут завершения объекта, а не видимости popup.
- Перечень решений, которые нужно провести через роутер, — раздел 4, B1.

### 3.4 Шторка передачи (handoff)
- Непрозрачная полноэкранная: пока она показана, карта, рука, ресурсы, панели не видны.
- Используется: (1) начало хода человека в хотсите; (2) передача для решения вне хода; (3) возврат.
- Реализация: расширить `PopupPanelUI` (не плодить второй модал) — режим «handoff» с
  `[SerializeField] GameObject handoffBackdrop` (полноэкранный непрозрачный фон). Пустая ссылка не должна
  ломать игру (без фона = текущее поведение). **Объект фона в сцене создаёт владелец руками**; агент пишет
  код с null-safe ссылкой и описывает ручной шаг в отчёте. Билдеры UI в рантайме запрещены
  (удалены 2026-11-07). Если всё же правится YAML сцены — оба инструмента `Tools/unity-yaml-verify`.
- В одиночной игре шторка ведёт себя как сейчас (небольшая панель без фона).

### 3.5 Правило наград — `MatchAccountOutcome`
Чистый (без Unity) класс-политика, тестируемый отдельно:
```
OnEliminated(player, livingHumansAfter) -> ParticipantResult? 
OnMatchFinished(survivors)               -> ParticipantResult?
```
- Поражение: публикуется, когда выбыл человек и живых людей больше не осталось → фракция этого человека.
- Победа: выживший один и он человек → его фракция.
- Если поражение уже опубликовано, победа AI ничего не публикует; дубль гасится и в `RewardService`
  (по `matchId`).
- Одиночная игра: результат идентичен текущему (выбытие единственного человека = поражение сразу).
- Кампания: не меняется (там один человек; сохранить текущую ветку `CampaignContext != null`).

| AI-наблюдатель (0 людей) | Без изменений (`_aiObserverMatch`, пауза/инспекция, `ObserverMatch`). |
| Кампания | Без изменений; хотсит невозможен. |
| Хотсит 2+ людей (+AI) | Ниже. |

### 5.2 Ход человека в хотсите
1. Непрозрачная шторка «Ход игрока B», карта не видна. Сиденье = null.
2. Подтверждение → зритель=B, сиденье=B, рука/ресурсы/панели B, затем ПВО начала хода B (как сейчас).
3. Ход B; конец хода — как сейчас.

### 5.3 Ход AI между людьми
- Зритель и сиденье остаются последним человеком, ходившим перед AI (как в одиночной игре: он видит
  ход AI в своём тумане). Перед следующим человеком — шторка.
- Скрытые бои AI-vs-AI — как сейчас.

### 5.4 Решения вне хода
- A атакует армию B ракетой/авиацией над ПВО B → шторка «Решение игрока B» → B видит только popup
  решения поверх непрозрачного фона (карта скрыта) → шторка «Вернуть игроку A» → ход A продолжается.
- AI атакует B во время хода AI, когда сиденье = A → то же через шторку.
- Если сиденье уже B (B — текущий) — popup сразу, без шторки (одиночная игра не меняется).

### 5.5 Бой H-H
- Полностью открыт, обе стороны интерактивны, рука тактик — действующей стороны, расстановка по очереди.

### 5.6 Выбытие и награда
- Выбыл человек, люди ещё остались → сообщение, матч продолжается, экрана наград нет.
- Последний человек выбыл → экран поражения (фракция этого человека), выход в меню как сейчас.
- Победил человек → экран победы (его фракция).

### 5.7 Сохранение
- Доступно на подтверждённом ходу любого человека. Загрузка → шторка текущего человека → его вид.
