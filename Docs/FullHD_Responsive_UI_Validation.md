# Адаптация Unity UI к Full HD

Ветка: `ui/fullhd-responsive-layout`. Unity: `6000.5.4f1`.
Начальная ревизия продолжения: `dd541fa6fb70ff6441e994490318f64973da3c4e`
(она уже содержала адаптацию размеров боевой сетки после `8b9f1d75`).
Master в рамках этой работы не изменялся.

## Выполненная реализация

- Сохранены Full HD настройки Player и CanvasScaler 1280×720. Масштаб Canvas для
  1280×720 / 1600×900 / 1920×1080 / 2560×1440: 1 / 1.25 / 1.5 / 2.
- Боевой экран растягивается по Canvas. Размеры ячеек определяет существующий
  GridLayoutGroup; полосы названия, характеристик, навыков и арт карточки привязаны
  к размеру ячейки. Подсветка действующего бойца читает действительный размер сетки.
- Боевая рука сохраняет четыре слота и равномерно масштабирует карточки по доступной
  ширине и высоте, не вмешиваясь в данные карт.
- Очередь инициативы получила обычные ScrollRect/RectMask2D/ContentSizeFitter.
  При смене бойца текущий элемент оказывается в видимой области; вся очередь доступна.
- Окна расстановки/исхода боя, событий, наград, выбора AA и общих сообщений центрированы.
  Подсказка полностью помещается под верхней границей Canvas.
- Панель хекса сохраняет два ряда навигации и четыре ряда ресурсов. Все пять состояний
  располагают доступные действия выше руки. Значения по умолчанию в C# согласованы
  с текущей высотой Canvas; зависимости от прежних 1024×768 в проверенных UI-скриптах нет.
- Карта и окно контакта используют прокрутку существующих списков армий. Ширина
  бокового списка соответствует префабу кнопки, поэтому кнопки не заходят на описание.
- Большие армии/гарнизоны прокручиваются внутри отдельной видимой области модального
  окна. ArmyViewerModalUI остаётся владельцем ручных координат карточек и высоты контента;
  ContentSizeFitter для этих ignoreLayout-карточек не добавлялся. Перестановка не принимает
  невидимые, обрезанные областью карточки за цели сброса.
- UIDragUtility преобразует экранный delta через фактический родительский RectTransform,
  включая вложенный масштаб и камеру Canvas. Существующие обработчики сброса,
  игровые проверки, AP/ресурсы и анимации сохранены.
- Настройка матча размещает шесть строк игроков с заданной высотой 40. Префаб PlayerRow,
  размеры контейнера и VerticalLayoutGroup согласованы.
- Длинные ряды кубиков инициативы используют размеры HorizontalLayoutGroup; квадратные
  изображения сохраняют пропорции. Боевые списки состава допускают уменьшение шрифта
  в заданном диапазоне 10–14.
- Убраны десять старых переопределений якорей ползунков AudioOptionsPanel в Game.unity,
  сжимавших их по вертикали. Ссылки настроек и загрузка сохранённой громкости сохранены.
- Удалён повторный YAML-ключ aiObserverPauseButton с тем же fileID. Все существующие
  GUID сохранены; для нового теста и ранее добавленного инструмента аудита есть .meta.

Это изменение представления и обработки UI-координат, без новых менеджеров и без изменения
игровых правил. ScrollRect, маски и контейнеры — стандартные элементы Unity UI.

## Выполненные проверки

- `python Tools/responsive-ui-verify/verify.py`: 25 сцен/префабов проходят проверку
  синтаксиса YAML, повторных ключей, Int64 ID, локальных ссылок, владельцев компонентов
  и двусторонней согласованности иерархии.
- Оба `Tools/unity-yaml-verify` инструмента проходят для всех 25 сцен/префабов.
- Расчёт сериализованных якорей для четырёх разрешений проходит: границы корневых
  панелей, боевая сетка, сетки базы и производства, рука, панель хекса и шесть игроков.
- Проверены связи областей прокрутки, маски карточек, версия Unity, настройки Player
  и цели переопределений префаба аудионастроек.
- `git diff --check` проходит.
- Добавлены `ResponsiveUiInteractionTests`; существующие `HexInfoDrawerTests` обновлены
  под текущую компоновку. Тесты охватывают вложенный масштаб перетаскивания, четыре
  тактические карты в ограниченной области и исключение скрытых целей перестановки.

## Не выполнено в этой среде

Unity Editor и Unity reference assemblies отсутствуют. Компиляция проекта и EditMode
тесты не запускались. Расчёт по YAML не подтверждает отрисовку текста, Unity layout pass,
physics raycast, drag-and-drop, сортировку Canvas/маски во время анимации и визуальную
корректность. Эти проверки перечислены в `Tools/responsive-ui-verify/README.md`.

Перед merge необходимо запустить проект в Unity 6000.5.4f1, полный EditMode suite и
перечисленные там сценарии на всех четырёх разрешениях. Визуальное подтверждение в
Game View остаётся обязательной частью приёмки; ветка подготовлена к этой проверке.
