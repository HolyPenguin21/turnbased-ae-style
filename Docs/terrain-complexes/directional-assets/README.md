# Отдельно освещённые ракурсы комплексов

Набор из 30 PNG подключён к пустынному биому через `GameConfig.asset`. Каждое семейство имеет шесть готовых шаблонов: 0°, 60°, 120°, 180°, 240°, 300°. Текстуры находятся в `Assets/Textures/Terrain/Desert/Complexes/Directional/`.

Используется существующий `HexMapGenerator.PlaceComplexes()` и `TerrainComplexPlacement.ChooseFromExclusiveGroups()`. Все 12 шаблонов остаются в единой группе `centerpiece`, с весом `count=1`. На карту выбирается один шаблон группы: вероятность каньона — 6/12, машины — 6/12; условная вероятность каждого ракурса — 1/6. После выбора прежнее распределение количества комплексов использует вес выбранного шаблона 1, как и раньше. Дополнительных независимых комплексов на карте не появляется.

Для всех шаблонов `randomizeRotation=0`: смещения и свет уже нарисованы. Геометрия и UV больше не вращают запечённые тени. При изменении весов семейства следует менять `count` всех шести его шаблонов одинаково, иначе изменятся вероятности отдельных ракурсов.

Степной биом (`AridSteppe`) сохраняет свои исходные изображения и палитру. Его механическое вращение отключено, пока для него не подготовлены отдельно освещённые ракурсы. Анимированные одиночные комплексы, правила размещения, проходимость и общий бюджет комплексов не изменены.

Версия 4 заменяет 25 новых PNG. Пять частей 0° остаются побайтно неизменными; все прежние `.meta`, GUID и ссылки конфигурации сохранены. Код генератора, смещения, веса и количество комплексов не менялись.

Предыдущая подгонка изображения проверяла лишь попадание рисунка внутрь раскладки. Поэтому в каньоне 60° одна часть фактически была песком: тёмный провал занимал 0,27% хекса. В v4 основа каждого ракурса — повёрнутые исходные части, с сохранением естественных изгибов и размера деталей. ImageGen выполнял правку света, затем скрипт выровнял песок по оригиналам. Каждый каньон проходит через три хекса; в новых частях провал занимает 11–22% площади хекса.

Нарезка использует фиксированную общую систему координат: диаметр хекса 400 при нормализованном размере исходника 1024. Независимая автоподгонка масштаба и положения удалена. Все части одного ракурса извлечены из единого непрерывного изображения. Цветокоррекция песка и контраста выполняется до нарезки; плавное поле поправки перекрывает общие границы. Тёмные провалы и нейтральные части машины защищены; пиксели изображения не сглаживались. Методику и коэффициенты содержит `palette-normalization.json`.

`visual-consistency.json` проверяет настоящую видимую грань каждого хекса, а не медиану всей квадратной текстуры. Максимальное отклонение среднего RGB песка новых частей от среднего оригиналов — 0,41 значения канала; средней яркости — 0,36. Это совпадение статистики песка, а не обещание идентичности всех пикселей. На всех 15 новых общих границах подтверждён непрерывный тёмный рисунок; максимальная средняя погрешность RGB при пересэмплировании — 1,651, 95-й процентиль — 5,944.

## Проверки

```sh
python3 Tools/terrain-assets/verify_directional_assets.py
python3 Tools/terrain-assets/audit_visual_consistency.py
node Tools/unity-yaml-verify/verify_full.js Assets/Config/GameConfig.asset
node Tools/unity-yaml-verify/verify_types.js Assets/Config/GameConfig.asset
```

Визуальному анализатору нужны `numpy`, `Pillow` и `scipy`. Он проверяет ровно три части каньона / две части машины, наличие рисунка в каждом хексе, цвет и яркость песка, непрерывность рисунка и погрешность на стыках. Тот же анализатор отклоняет предыдущий набор v3, включая исходный дефект пустого хекса, и принимает v4. Проверка ссылок сверяет смещения, хеши PNG, уникальные GUID, sRGB/Clamp, отключение вращения и равенство весов семейств.

В среде доставки нет Unity и .NET; редактор, C#-тесты и игровой запуск этой версии не выполнялись. Код C# не менялся. Перед визуальным принятием открыть проект в Unity 6000.5.4f1 и проверить все 12 шаблонов при игровой камере: направление света, естественные изгибы, размеры деталей и переход к обычному песку. Проверки PNG и YAML не заменяют проверку движка.
