## 1. Actual path / owners

`WorldAnalysis.Scan` creates `WorldSnapshot` containing Self, Known/TrueWorld, Economy, Threat and map observations; subsequent `RefreshOperationalState`/`RefreshStrategicKnowledge` refresh respective settled facts. `ReconObjectiveEvaluator.Enumerate` owns Explore/Refresh/Surveil TaskScore; `AggressionObjectiveEvaluator.Enumerate` owns Raid target relevance/staleness gate; `DemandLayer.EconomyDemands` and its `AddBaseCandidates` own Extraction/Base TaskScore (site-only fact -> full delivered value after choosing a builder). `TaskScoreEvaluator.Fold` is the one arithmetic slot/fold owner. `AiStrategyV2Pipeline` owns objective enumeration and settled-step re-admission, `MissionContinuityLayer.ResolveActive` owns durable state and valid actors, `DemandLayer.Generate` owns capability demands, and `StrategicPhaseA.FulfillDemands` spends shared AP/materializes capabilities BEFORE constructing missions.

`ReconMissionPlanner.Propose` passes scored objective value; `AggressionMissionPlanner.ToCandidate/BuildProposal` adds actual projected win chance, raid activation/distance to target relevance and preserves a committed primary; `EconomyMissionPlanner.Propose` passes `AxisDemand.Value`, not site-only merit, for new work, and rehydrates the pinned actor and either refreshed full value or saved `EconomyIntent.IntrinsicValue` for an active intent. `AiStrategyV2Pipeline.BuildMissionSet` stamps `EffectiveValue` with the radar scale once. `MissionAdmissionPolicy.AdmissionRank` uses local score inside a lane; Economy adds a same-turn completion bonus and local urgency only there; it must not reprice card/delivery. `ResourceAllocator.BeginTurn` / `AllocationSession.Pack` protects hard/soft commitments before a true cross-lane merge of lane heads by `EffectiveValue`; it enforces available AP, the single H/E/M/T vector, cooldowns and pair conflicts. `ReconAssignmentPlanner` and `GroundCombatAdmissionRegistry` settle actor availability; `ProvisioningManager` revalidates, reprices or rejects and `AllocationSession` re-packs a bounded number of times. `TaskExecutor.ExecuteStep` uses real game legality and actual costs; `MissionOutcomeLedger` + `MissionContinuityLayer.ReconcileStep/ReconcileAfterTurn` persist actor, age, outcome, return/refocus, failure/cooldown and reservation cleanup.

Value contracts: `TaskScore.Value = positives - costs`; `BaseValue` is transported intrinsic value; `EffectiveValue = BaseValue × radar scale`; `LocalAdmissionScore`/`AdmissionRank` are only within-lane priority and explicitly policy-based. `EconomySiteValue`/`EconomyIntent.BuildValue` are **site-only**, not equivalent to `Value`/`IntrinsicValue`. `ContinuationValue` currently receives proposal BaseValue, `SwitchingCost` is zero in `BindFunding`; the allocator does not yet use them for pre-emption. Urgency (base waiting) is not a TaskScore slot, but it can change candidate filtering, lane-local order and Phase-A Play-vs-Hold. `StrategicPhaseB.UseSurplus` uses its own `StrategicCardEvaluator.NetScore`/Hold evaluator *after* missions; Development/Production materialization uses Phase-A portfolio, not direct candidates in the Scout/Raid/Economy allocator. Defence is folded into the Aggression axis; there is no separate live Defence demand axis.

Recompute: early recon/aggression observations are initially frozen for the turn; Phase A refreshes operational Self/Economy if it mutates state. In the typed settled-command loop the snapshot, reconnaissance objectives and aggression opportunities are refreshed after state changes; `DemandLayer` only regenerates dirty strategic axes. Economy mission value may fall back to captured `IntrinsicValue` if no matching refreshed demand; route and AP for the pinned actor are recomputed by `EconomyMissionPlanner.Requirements` and proved in provisioning. Raid reassembles and reprices for pinned primary. Rejections independent of score: objective gates, payback/meaningfulness, legal card/hex, scope, AP/physical pool, actor/target conflict, cooldown, no actual executable step, combat WorthIt, and structural failure.

## 3. CONFIRMED defects (not tuning hypotheses)

### F1 — locked AP omitted from hard-commitment ceiling

`Assets/Scripts/Ai/V2/Allocation/ResourceAllocator.cs`, `AllocationSession.Pack`, one owner. `lockedTotal` sums already-provisioned real AP and is debited from the allocatable budget, but the Hard/Soft loop's ceiling currently checks `committedApSoFar + askAp > pool.Ap + eps`, omitting `lockedTotal`; global overdraft diagnostics happen after funding. Example: pool 3AP, Scout Hard locks 2AP, Raid Hard asks 3AP -> repack passes its guard (3≤3), has total 5, overdraft2. Surgical patch:

```diff
- if (committedApSoFar + askAp > pool.Ap + eps)
+ if (lockedTotal + committedApSoFar + askAp > pool.Ap + eps)
```

The same physical AP is counted once, and existing budget provenance, other resource checks, legality, ordering and cooldowns are unchanged. `Assets/Editor/AiTaskScoreAllocatorRegressionTests.cs` reproduces first-pass deferral -> locking -> re-pack and asserts no Raid funding / zero overdraft. Test is **committed but NOT run; production patch NOT applied**.

### F2 — base switch compares canonical new merit against site-only old merit

`Assets/Scripts/Ai/V2/Strategy/StrategicPhaseA.cs`, `StrategicPhaseA.FulfillDemands` / `supersedingBaseSite`. Code checks `d.Value > protectedActiveBase.Economy.BuildValue + economyBaseSwitchHysteresisThreshold`. New `d.Value` includes costs/delivery while old `BuildValue` is site-only. Example old site40/delivered20, new site38/delivered34: real intrinsic gain14 exceeds hysteresis10, code tests 34>50 and refuses. Fix at existing switch decision owner: locate old candidate's **fresh canonical delivered** `Value` when present, otherwise last canonical `Economy.IntrinsicValue` for an explicitly valid incumbent, then compare like to like. Preserve `BuildValue` as separate operational/site fact, require same card and validated legal target, do not weaken commitment hysteresis. A direct Phase-A switch regression with competing legal sites plus a missing-old-refreshed-demand case is needed; **not implemented**.

### F3 — base challenger pruned before Phase-A switch logic

`Assets/Scripts/Ai/V2/Strategy/Demand/DemandLayer.Economy.cs`, `EconomyDemands`: `baseRanked` orders `IsActiveBaseCommitment` first, then `.Take(economyMaxExpansionBaseDemandsPerTurn)` with cap=1 (`AiConfigV2.DemandConsumers.cs`). With an eligible incumbent present the challenger is absent from `demands`; `StrategicPhaseA.supersedingBaseSite` searches `demands` only for a *different* hex, so it cannot exercise its switch condition in that normal case. To fix, keep one actual executable Base demand, but make the **existing** candidate-selection owner choose whether a challenger clears the correctly computed old/new canonical value + existing hysteresis and publish the proper replacement decision to the existing Phase-A/Continuity owners; ensure old durable intent releases card, actor and reservation before new one claims them. Do **not** globally raise the demand cap to two or discard live commitments. No source fix/test implemented; a high-value challenger vs incumbent regression through Demand→Phase-A→Continuity is required.

## 4. Not confirmed as bugs; preserve until real logs

- Raid +12 win bonus: target-discovery gate requires positive target relevance; actual event loot is not fully represented by the defender-power proxy. Need paired target loot, Monte Carlo WorthIt, AP, distance, chosen/suppressed candidates and battle reward ledger before changing win/relevance coefficients.
- Base front progress, corridor, own proximity: sourced from distinct measurements (direction toward enemy, route detour, nearest own base). They are correlated but not shown to count the same **physical expense** twice. Need geometric site pairs and selected site outcomes, economy payback and actual defended area. Spacing is diagnostic/legal, not another TaskScore bonus.
- Recon `ScoutCostModel.Estimate` uses nearest home and notional actor/AP to rank objectives; assignment/provisioning use actual actor/route, with retry/reprice. Whether distant tasks are systematically overvalued needs planned-versus-actual actor, observation vantage, safe-route MP, real AP and failure/reprice telemetry.
- Extraction ROI/short vs long return: payback horizon 8 and profitability gate are explicit policy, resource demand derived from hand/deck; actual multi-turn ROI needs income ledger by type, opportunity cost of lost army, elapsed delivery, deck/hand demand and competing ActionPoints. Do not change coefficients from these synthetic cases.
- Durable Economy can fall back to captured `IntrinsicValue` without a matching refreshed demand; structural invalidation exists, but sustained low value or `MoverContended` is not proven to have a universal bounded stop for Extraction. FoundBase has a consecutive delivery-failure suppression; ordinary Scout/Raid have reaping/cooldown paths. Capture consecutive attempts, stable key, actors, route, reservation and failure disposition to prove a liveness regression; do not silently delete valid commitments.
- Development's pre-migration utility/urgency band differs from 5..12, but Phase A selects capability actions before map-mission allocation; Phase B is a separate, later tempo arbiter. A numerical mismatch alone is not proof of a shared-comparator bug. Capture actual Phase-A portfolio ranking and AP/HEMT reservations vs subsequent available missions before changing these families.
