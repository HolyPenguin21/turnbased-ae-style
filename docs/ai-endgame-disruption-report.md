# ИИ: завершение штурма и Disruption

Дата: 26.10.2026. Масштаб: исправления поведения в существующей ARCH-02, без новой оси или менеджера ИИ. Работа продолжена из существующего diff в `work/ai-endgame-disruption`. После отдельного разрешения владельца PR #237 слит в master (`e93f58cb5c79fb8efb178a0d7b62d29c84aa04c7`); затем выполнена повторная проверка снизу вверх.

## Реализованные девять пунктов

1. **Refresh:** lookahead больше не оправдывает шаг без непосредственной пользы; полезный транзит и Explore сохранены.
2. **Gather и защита баз:** план оценивает итоговый состав и расположение всех доноров; переходы обычного Gather и preparation в Assault проходят политику выхода. Совместный уход нескольких доноров не может превратить удерживаемую собственную базу в не удерживаемую только потому, что удалённый host не успевает вернуться. Все production callers Gather передают проверку выхода, включая Demand и Continuity.
3. **Маршрут:** контакт оценивается на фактическом пути по ходам с текущими и максимальными MP. Память противника в FoW остаётся честной; её истечение само по себе не очищает запомненную вражескую базу.
4. **Усиление и preparation:** запрещается потеря существующего исполнимого маршрута конкретной задачи, а не любое замедление. Перебираются подходящие альтернативы героя и состава. Полный закреплённый preparation-состав проверяется до первого переноса; отказ не меняет армии частично.
5. **Экономика:** обязанности оператора и выбор preparation-site проверяются на проектируемом составе с новым героем, с заменой прежней армии в проекции, до оплаты.
6. **Ракеты:** независимый полезный подготовительный удар проходит существующую цепочку air support: цель, финансирование, обеспечение, перебазирование/запуск, повторная проверка полезности, урон и завершение. Успешно израсходованная ракета не считается потерянным исполнителем. Собственные базы защищены от сознательно разрушающего их подготовительного удара.
7. **Прогноз и отступление:** добавлены коррелируемые записи seed, состава, замороженной защиты здания и оценок на 2/3 раунда. Пороги отступления не менялись без доказанного дефекта.
8. **Диагностика:** сообщения завершения отражают реальную фазу; Scout-ключи различают Hunt, CaptureStructure и DisruptStructure.
9. **Disruption:** существующий `concord.card.scout` получил способность. Живой враждебный наземный носитель на хексе либо во входящей армии снимает только положительную защиту здания. Terrain, Defense и Guarded сохраняются. Эффект не складывается, не раскрывает носителя, фиксируется на начало каждого боя; следующий бой заново проверяет присутствие. Прогноз, coverage, кэши и память учитывают тот же building-компонент. ИИ доставляет скрытого носителя существующей Scout-миссией или сохраняет его в ударном составе.

## Закрытые остатки и проверка связей

- Доставка проверяет hard-block конечного хекса и каждого шага, detector risk и текущие MP. Штурм ждёт только Active доставку скрытого носителя в этот ход, без дополнительных AP на активацию. Уже прибывший или встроенный носитель ожидания не требует.
- `AssaultNeedsDisruption` учитывает только Active Attack-intents. Тестовые `MissionIntent` задают `Objective`, а не getter `Scout`.
- `rosterAdmissible` проведён через preparation-сборку, выбор героя и все production callers; приоритет Disruption в same-hex сборке сохранён.
- Проверена цепочка: способность → BattleState/BattleEngine/UI → WorthIt/coverage/cache → FoW → сборка/preparation → admission/demand/provisioning → execution → continuity/retirement. Независимый read-only обзор обнаружил брешь с совместным уходом доноров; она исправлена и покрыта новой регрессией.

Основные владельцы: `Missions/Attack/AttackMarchPolicy`, `Missions/GroundCombat/GroundCombatAssemblyPlanner*`, `GroundCombatReinforcement`, `GroundCombatAirSupport*`, `ReconAssignmentPlanner`, `AttackExecutor`, `ReconGroundExecutor`, `AttackContinuity`, `DevelopmentOpportunityEvaluator`, `DisruptionRules`, `BattleState`, `BattleEngine`, `WorthIt` и связанные существующие demand/provisioning owners. Точный список — diff ветки.

## Повторная проверка после слияния #237

Проверка начата после подтверждения remote master `e93f58c`. Прослежены также существующие потребители, которые не входили в первоначальный diff: прямое усиление из руки, local refit полной подготовки, ожидание held/generated/undrawn карты и повторная проверка перед оплатой.

Обнаружены и исправлены два связанных пропуска:

- **Собственная preparation получала отказ по committed actor.** Общий фильтр свободной полевой мощности отвергал прямую карту в host своей же активной операции; одновременно local refit справедливо не предлагался при наличии свободного слота. Теперь исключение допускается только для точного ConsumerIntentKey, своего PrimaryArmyId, Active preparation в Gather без начавшегося Assault. Чужие claims и IndependentFieldArmy остаются защищены. Результат доставки по-прежнему измеряется по росту мощности конкретного host. При копировании residual-demand из Phase A в Phase B сохраняется ConsumerMissionKind, чтобы это же исключение работало в обоих этапах.
- **Карточное усиление могло уничтожить маршрут.** Полный preparation refit не передавал task-route predicate в общий handoff solver. Теперь он передаётся до выбора состава и повторно проверяется при Validate/исполнении. Прямая карта использует полный проектируемый состав, включая Transport; проверка повторяется перед первой оплатой цепочки. В preparation-demand передаётся существующее поле AttackObjectiveHex. Условие WAIT для held/generated/undrawn карты использует тот же маршрут для прямой доставки или реального обмена. Допустимое замедление сохраняется.

Добавлены параметризованные регрессии в `AiAttackBaseRefitTests`: собственный и посторонний consumer; полный refit и свободный слот при MP1/MP2 на пути с terrain cost 2; отказ устаревшего pinned refit; согласованность WAIT и execution-time target lookup. NUnit не запускался.

Повторно выполнены `git diff --check`, дифференциальный tree-sitter разбор 86 изменённых C# (три прежних parser limitations без изменений), оба YAML-валидатора, проверки новых GUID и всех production Gather/preparation predicates. Прогнозы, кэши и FoW проверены по исходникам; независимый read-only обзор подтвердил два дефекта выше и не обнаружил иных подтверждённых Critical/Important в проверенных missile/Gather lifecycle paths. Компиляция и Unity/EditMode остаются невыполненными.

В GitHub Actions исходного PR есть **существующее падение terrain-assets validator**: `Tools/terrain-assets/validate.py:27` ожидает другое количество комплексов. В исходном master AridSteppe Boiling mud field имеет count 3 вместо ожидаемого 1; Desert Acid lake имеет count 3 вместо ожидаемого 2. Полная секция mapGeneration совпадает с baseline; наш GameConfig diff меняет только подпись Disruption. Проверка алгоритмов terrain в том же CI дала 51 passed / 0 failed на managed stubs; это не проверка ИИ и не Unity compilation. Посторонние terrain-настройки в рамках этой задачи не изменялись.

Дополнительный Unity-сценарий: preparation с одним свободным слотом получает карту от собственного demand, но не от другого ConsumerIntentKey. Для полного и неполного host проверить более сильные MP1/MP2 карты на единственном пути с terrain cost 2: MP1 не покупается и не удерживает WAIT, MP2 допускается.
