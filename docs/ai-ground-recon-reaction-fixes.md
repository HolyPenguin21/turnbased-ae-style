# Наземная разведка: доступность атаки и отсутствие пути отступления

Исходный и повторно проверенный master: `a0dd0468b2fd43f29ac09c463c0f4d5e2a63a0d1`.
Прочитаны актуальные `AGENTS.md`, `Assets/Scripts/Ai/V2/ARCHITECTURE.md` и
`Tools/ai-verify/README.md`. Unity проекта: **6000.5.4f1**.

## Причины и изменения

### 1. Недостаточное движение для атаки

`ReconReactionPolicy.FindWeakScoutOpportunity` проверял проходимость и текущую
видимость соседней цели, но не её стоимость входа относительно CurrentMovement.
Регрессионные сценарии на исходном runtime выбирали AttackOpportunity при
стоимости 3 и остатке 2, а также при нулевом остатке движения.

Добавлен ранний gate через **AviationRules.MovementCost** — существующий владелец
фактической стоимости шага, который используют ArmyController и приём приказа
HexSelectionController. Формула не копируется. Неоплачиваемая цель исключается;
при отсутствии другой реакции Evaluate возвращает Continue для обычного
ReconGroundStepPlanner. Проверки видимости, состава цели, покрытия урона,
вероятности победы, критического состояния и позиции после боя сохранены.

### 2. Отсутствие безопасного выхода

Первоначальная формулировка нуждалась в уточнении. PickFleeTarget **уже перебирает
все соседние клетки** и более дальние кандидаты внутри радиуса, проверяя
ScoutExecutionSafety и первый шаг того же SafeStepPathing, который вызовет
исполнитель. Если хоть один безопасный оплачиваемый сосед существует, он сам
является кандидатом, даже когда путь к гарнизону отсутствует. Подтверждения
отдельного дефекта «пропущен другой доступный безопасный путь» нет.

Подтверждён дефект запасного результата: когда кандидатов нет, возвращался
NearestOwnGarrisonHex без этих проверок. Тесты воспроизвели как недоступный
гарнизон, так и возврат занятой опасной клетки гарнизона. Общий маршрутизатор
имеет намеренное исключение блокировки назначения, поэтому такая запасная цель
не могла считаться безопасной только по факту наличия пути.

PickFleeTarget теперь возвращает nullable цель: непроверенный home fallback
удалён, близость к своим гарнизонам остаётся прежним компонентом оценки.
При отсутствии кандидатов политика возвращает Flee без цели с явной причиной
hold position. Исполнитель заканчивает движение с NoSafeStep, CanContinue=false,
без команды, AP, расхода MP или изменения версии мира. Обычное планирование
после этого не направляет разведчика обратно в угрозу. Перед командой Flee
исполнитель также проверяет фактический первый шаг через ScoutExecutionSafety.

Завершение движения здесь — безопасный запасной результат. Оно не означает
нового запрета на будущие ходы, обнуления MP или гарантированной неуязвимости
на текущей клетке. Правила Stealth и обнаружения не меняются и скрытность
автоматически не покупается ради этой остановки.

## Прослеженные ветки и владельцы

- **Единственный V2 владелец реакций:** ReconReactionPolicy. Аналогичные старые
  V1 planners не используются для этих решений и не изменены.
- **Маршрут:** SafeStepPathing → AiTurnController.FindAffordableStep →
  HexPathfinder.FindPathByTurns. Применяются текущие MP, максимум MP, terrain
  blockers, честная память и существующий профиль Standard; поиск не перенесён
  в Execution и не продублирован.
- **Run и RunStep:** обе формы используют RunPreparedStep. Реакция выбирается
  заново перед каждым шагом после завершения предыдущей команды. Между Evaluate
  и проверкой маршрута нет coroutine yield. StopAndReplan, потеря/смена состава
  актёра, активный бой и OutOfMovement сохраняют свои ранние выходы.
- **Остальные реакции:** EvadeDetector, AttackOpportunity, SabotageStructure и
  Continue сохраняют свою обработку. Funded CaptureStructure имеет собственные
  проверки и переопределение реакции; контакт скрытого резидента остаётся до
  проверки MP. Это отдельная механика и этим исправлением не меняется.
- **Результат:** NoSafeStep уже нормализуется в Waiting. Это окончание текущего
  действия, а не доказательство структурной неисполнимости цели. Continuity
  сохраняет существующее управление ожиданием и stall aging.
- **Банк/claims/cache:** новых расходов, резервов, intents или владельцев не
  добавлено. Не меняются allocator, provisioning, leases, memory revisions,
  маршрутный cache и combat estimator. Нет сохранённого blocked flag;
  изменившиеся данные карты позволяют снова выбрать выход.

Масштаб: локальное исправление поведения двух существующих владельцев;
архитектура, коэффициенты, боевые расчёты и правила обнаружения не менялись.

## Регрессионные проверки

Новый `Assets/Editor/Tests/AI/AiReconGroundReactionRegressionTests.cs` содержит
25 cases: дорогой рельеф, достаточные/недостаточные/нулевые MP, минимум стоимости
входа, fog, neutral, garrison, prison, non-scout target, hidden target,
non-combat mover, coverage, losing battle, critical-after risk, unsafe
post-combat position, недоступный гарнизон с доступной альтернативой, отсутствие
соседей/доступных MP, частично заблокированный путь, занятая клетка в том числе
гарнизон, обе формы исполнения без команды/зацикливания/расходов, Waiting и
повторный выбор после открытия пути.

| Проверка | Результат |
|---|---|
| Baseline до изменений runtime | 1377/1377 passed |
| Новые сценарии на исходном runtime (24 cases до добавления второй формы Run) | 17 passed, 7 ожидаемых assertion failures; ошибок среды после адаптации нет |
| Исправленный runtime, новые сценарии | 25/25 passed в managed проверочной копии |
| Прежняя переносимая suite после исправления | 1377/1377 passed; все исходно проходившие cases сохранены |
| Differential compile | Те же четыре ошибки reference/stub среды в UI/Audio, новых нет |
| Сборка тестовой копии | Без ошибок; новые native tests компилируются |
| Whitespace | git diff --check пройден |

**Границы проверки:** Unity и полная native EditMode suite здесь не запускались.
Регрессионный fixture предназначен для настоящего HexMap в Unity. Для выполнения
его в Mono отдельная проверочная копия заменяет создание компонента на
uninitialized HexMap с его фактическим data dictionary, Unity object equality
на reference equality и Vector3 для геометрического tie-break на managed
эквивалент. Также применяются прежние .NET 4.7.2/stub адаптации ai-verify.
Маршрутизатор, фильтры, расходы движения, боевые оценки, реакции и coroutine
исполнителя остаются фактическим кодом. Ни один из этих адаптеров не входит
в игровой проект; этот прогон не доказывает native Unity acceptance.

Перед приёмкой в Unity 6000.5.4f1 запустить новый fixture и полную EditMode suite,
затем проверить разведчика возле дорогой цели, отступление обходным путём и
остановку в ловушке без входа в известную опасную клетку.
